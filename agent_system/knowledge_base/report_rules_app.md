# APP业务线 日报规则（独立模板）

> 最后更新：2026-03-02
> 对应脚本：generate_app_full_report.py + app_report_data.py + app_report_html.py
> 数据来源：3张表（daily 51字段 + orders 20字段 + traffic 16字段）

---

## 一、业务定位

APP是珍爱网「在线付费产品」体系的核心现金牛。通过DAU驱动的流量转化实现规模化营收，是公司**现金流压舱石**和**全公司流量水库**。

**关键飞轮：** 用户增长 → 匹配质量 → 付费意愿 → ARPU → 再投入增长

**双重角色：**
1. **在线营收引擎**：珍心会员/超级会员/直播守护等产品矩阵
2. **线下导流枢纽**：为门店/建信/邀约等业务线输送leads

## 二、数据表与字段全量映射

### 2.1 daily表（51字段，按用途分组）

**营收核心：**
- `amt` → 日营收（北极星指标）
- `pay_num` / `pay_num_new` → 付费人数 / 新增付费
- `fugou_amt` → 复购金额（占比>50%为健康）
- `pay_amt` → 支付金额
- `refund_money` → 退款金额（退款率红线<2%）

**用户规模：**
- `active_members` → DAU（流量基石）
- `mems` → 新注册人数
- `reg_num_m` → 月累注册

**留存矩阵：**
- `retain_1d` ~ `retain_30d` → 9个留存节点（1/2/3/4/5/6/7/15/30日）

**直播板块：**
- `anchmems` → 开播主播数
- `anchtime` → 总直播时长（秒）
- `giftmems` → 送礼人数
- `costmoney` → 直播消费金额
- `live_guard` → 直播守护收入

**订单漏斗：**
- `order_cnt` → 订单创建数
- `order_pay` → 支付成功数
- `order_num` → 订单人数
- 支付失败率 = (order_cnt - order_pay) / order_cnt × 100%

**产品品类（9个）：**
- `zhenxin_member` → 珍心会员（红线：占比<80%）
- `super_member_full` / `super_member_plus` → 超级会员全/+
- `live_guard` → 直播守护
- `zhenai_coin` → 珍爱币
- `super_remind` / `star_privilege` / `super_recommend` / `other`

**跨业务协同：**
- `leads_offline` / `leads_online` → 线下/线上leads
- `allot` / `laoqu` → 分配/捞取
- `link_1d_num` / `callout_1d_num` → 链接数/外呼数

**月累计：**
- `pay_num_m` / `pay_amt_m` → 月累付费人数/金额
- `pay_num_m_cut` / `pay_amt_m_cut` → 月累去重
- `amt_pay_m_online1` → 月累在线营收
- `last_consumeonday_d` / `last_consumeonday_m` → 最后消费日统计

### 2.2 orders表（20字段，订单明细）

**多维度聚合：**
- `entrance1` / `entrance2` / `entrance3` → 三级入口（直播/非直播→消息页/爱情钥匙等→细分场景）
- `channelname` / `channelname2` → 支付渠道（微信支付/IOS/支付宝等）
- `platformname` → 平台（iOS/Android/小程序/鸿蒙/WAP/PC）
- `producttype` / `productfullname` → 产品类型/产品全名（含价格档位）
- `user_type` → 用户类型（普通用户/风险用户）
- `is_trial` → 是否试用
- `iscallback` → 支付回调状态
- `app_version` → APP版本

### 2.3 traffic表（16字段，渠道质量）

- `parent_name` / `parents` → 渠道大类/子渠道
- `regnum` / `regnew_mems` → 注册数/新注册会员
- `num_pay_online_d` → 日付费人数
- `amt_pay_d_online` / `amt_pay_m_online1` → 日/月在线营收
- `real_cost` → 投放成本
- `validnum` → 有效用户数
- `pay_online_rate` → 付费率

## 四、APP特有分析规则

### 4.1 交友APP运营特殊性（书籍映射）

| 特殊性 | 书籍来源 | 数据映射 |
|--------|---------|---------|
| 留存驱动力=社交关系链 | 《Hooked》 | retain_1d~30d |
| Aha时刻=被异性喜欢 | 《增长黑客》 | 首日留存+link数 |
| 产品本质=匹配效率分层销售 | 《订阅经济》 | 产品品类占比 |
| 虚拟商品=社交货币 | 《平台革命》 | zhenai_coin/live_guard |
| 成功悖论：找到对象=流失 | 《用户增长方法论》 | 复购率/新客依赖 |
| 直播=信任建立场景 | 《平台革命》 | 直播支付率>非直播 |
| 情感冲动支付 | 《怪诞行为学》 | 支付失败=永久流失 |
| 损失厌恶>获得快乐 | 《用户增长方法论》 | 付费前展示「错过了什么」 |

### 4.2 关键红线

- 珍心会员占比 > 80%：产品结构高风险
- 退款率 > 2%：需专项治理
- 支付失败率 > 40%：P0紧急
- 次日留存 < 35%：根本问题
- 付费率 < 3%：转化路径有严重障碍
- 渠道ROI < 0.3：立即砍预算

### 4.3 评分逻辑

APP无传统的「过程+结果」评分。APP评分100%与营收/转化指标关联：
- 30% 日营收达成率（vs月度目标日均）
- 25% 付费率（基准5%）
- 20% ARPU（基准¥30）
- 15% 留存率（基准次日40%）
- 10% 产品健康度（珍心<80%、退款<2%）

## 五、每个问题必含业绩预估规则

每个诊断问题、改善建议、知识对撞都**必须**包含具体业绩预估：
- 格式：`日增¥X，月增¥Y`
- 预估方法：基于当前数据的线性/比例推算
- 举例：留存+5pp → 有效池扩大N人 × 付费率 × ARPU = 日增¥X

## 六、KPI卡片迷你趋势线（Sparkline）

每个KPI卡片在数值下方嵌入一条迷你SVG趋势曲线，展示该指标近10天走势：

- **技术方案**：纯内联SVG polyline，零依赖，支持HTML邮件和浏览器
- **数据来源**：APP通过并行API拉取10天daily数据；其他业务线通过SQLite情景记忆
- **视觉规则**：
  - 宽60px × 高22px，嵌入卡片内
  - 线条颜色与卡片主题色一致
  - 末端圆点：绿色=上升趋势，红色=下降趋势
  - 曲线下方半透明填充增强可读性
  - 数据不足2天时不显示（优雅降级）
- **APP覆盖指标**：DAU、次日留存、付费率、ARPU、日营收、复购金额、退款率、订单成功率
- **工具模块**：`agent_system/actions/report_sparkline.py`
  - `sparkline_svg(values, width, height, color, fill)` → SVG字符串
  - `extract_trend_values(history, key, today_val)` → 从情景记忆提取趋势值列表

## 七、技术架构

- **模块化拆分**：data.py(聚合) + html.py(渲染) + main.py(主控)
- **并行API**：14次API调用并行（含10天趋势），0.4秒完成
- **情景记忆**：SQLite存储每日关键指标，自动7日均值对比
- **报告大小**：~73KB（20+分析模块 + sparkline）
